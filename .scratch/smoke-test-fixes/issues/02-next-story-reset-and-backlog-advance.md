# 02: "Next Story" Fails to Advance Backlog and Reset Previous Round Votes

**Category:** `bug`
**Status:** `ready-for-agent`
**Blocked by:** none

## Problem Statement

When the Facilitator finalizes a story and clicks "Next Story", the room does not clear previous votes or advance to the next story in the backlog. Instead, the room immediately shows as already "voted", retaining all participant votes from the previous story round.

## Verified Codebase Behavior

1. In `client/src/components/FacilitatorBar.tsx` line 117, when `phase === 'Finalized'`, the "Next Story" button calls `onClick={onStartVoting}`.
2. In `shared/src/room-reducer.ts`, `START_VOTING` only switches `phase: 'Voting'` without clearing participants' `has_voted` and `vote` values:
   ```typescript
   case 'START_VOTING': {
     return {
       ...state,
       phase: 'Voting',
       consensus: null,
     };
   }
   ```
3. Furthermore, clicking "Next Story" does not advance `current_story` to the next unestimated story from `backlog`.

## Agent Brief & Acceptance Criteria

- [ ] **Next Story Reducer / Action**: Add a dedicated `NEXT_STORY` (or update `SET_STORY` / `START_VOTING`) action in `@scrumpokr/shared` and server routes.
- [ ] **Backlog Advancement**: When "Next Story" is triggered:
  - If stories remain in the `backlog`, the next story is set as `current_story` (and removed or marked completed in the backlog).
  - If no backlog stories remain, `current_story` is set to null or a fresh story creation prompt.
- [ ] **Vote & Round Reset**:
  - All participants have `vote: null` and `has_voted: false`.
  - `consensus` is reset to `null`.
  - `phase` transitions to `Idle` (ready for voting).
  - Round counter is incremented.
- [ ] **Automated Tests**: Unit and integration tests verifying backlog advancement, complete vote wiping, and clean state for subsequent estimation rounds.
