# 02: Hono SSE Stream Lifecycle & Reveal Gate Fan-out Masking

Type: research
Status: resolved
Blocked by: none

## Question

How should Hono's `streamSSE` and in-memory `RoomRegistry` be architected on Node.js (`@hono/node-server`) to manage per-participant streaming connections, keep-alive heartbeats, clean resource de-registration on client abort, and real-time Reveal Gate state masking?

## Background & Context

- In Java Spring Boot, `RoomRestController` used `SseEmitter` instances stored in `ConcurrentHashMap<String, List<SseEmitter>>`.
- In Hono, `streamSSE` provides an async streaming closure with `stream.writeSSE()` and `stream.onAbort()`.
- The architecture must guarantee:
  1. Safe multi-client SSE fan-out when state mutations happen (voting, revealing, resetting).
  2. Strict server-side Reveal Gate enforcement: when in `Voting` phase, participant `vote` fields are masked to `null` while `has_voted` is preserved.
  3. Non-blocking keep-alive heartbeats (`: heartbeat` or `event: ping`) to prevent corporate proxy and cloud load balancer disconnects.
  4. Instant unsubscription and memory leak prevention when browser tabs close or refresh.

## Answer

### 1. Hono `streamSSE` Architecture

In Hono with `@hono/node-server`, the SSE route `/api/rooms/:code/events` manages long-lived connections with automatic header configuration (`Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`, `X-Accel-Buffering: no`):

```typescript
// server/src/routes/events.ts
import { Hono } from 'hono';
import { streamSSE } from 'hono/streaming';
import { roomRegistry } from '../room/registry';

export const eventRoutes = new Hono()
  .get('/api/rooms/:code/events', async (c) => {
    const code = c.req.param('code');
    const participantId = c.req.query('participantId') || '';

    const room = roomRegistry.getOrCreate(code);

    return streamSSE(c, async (stream) => {
      // 1. Initial State Push (Masked for this specific participant)
      const initialState = room.getMaskedState(participantId);
      await stream.writeSSE({
        event: 'room_state',
        data: JSON.stringify(initialState),
      });

      // 2. Subscribe to room broadcasts
      const unsubscribe = room.subscribe(participantId, async (maskedState) => {
        try {
          await stream.writeSSE({
            event: 'room_state',
            data: JSON.stringify(maskedState),
          });
        } catch (err) {
          // Socket write failed, cleanup will trigger on abort
        }
      });

      // 3. Lifecycle cleanup when client closes tab / disconnects
      stream.onAbort(() => {
        unsubscribe();
        room.handleParticipantDisconnect(participantId);
      });

      // 4. Non-blocking keep-alive heartbeat loop (15s interval)
      while (!stream.aborted) {
        await stream.sleep(15000);
        await stream.writeSSE({
          event: 'ping',
          data: 'heartbeat',
        });
      }
    });
  });
```

### 2. In-Memory `Room` Actor & Reveal Gate Fan-Out

Because Node.js executes state modifications sequentially on its event loop, room state mutations are atomic without Java-style locks (`ReentrantLock`):

```typescript
// server/src/room/room.ts
import { maskRoomStateForParticipant } from '@scrumpokr/shared';
import type { RoomState } from '@scrumpokr/shared';

type Subscriber = (maskedState: RoomState) => Promise<void> | void;

export class Room {
  private state: RoomState;
  private subscribers: Map<string, Set<Subscriber>> = new Map();

  constructor(public readonly slug: string, public readonly shortCode: string) {
    this.state = this.createInitialState();
  }

  public subscribe(participantId: string, callback: Subscriber): () => void {
    if (!this.subscribers.has(participantId)) {
      this.subscribers.set(participantId, new Set());
    }
    this.subscribers.get(participantId)!.add(callback);

    return () => {
      const set = this.subscribers.get(participantId);
      if (set) {
        set.delete(callback);
        if (set.size === 0) {
          this.subscribers.delete(participantId);
        }
      }
    };
  }

  public broadcast(): void {
    const raw = this.state;
    this.subscribers.forEach((subSet, participantId) => {
      const masked = maskRoomStateForParticipant(raw, participantId);
      subSet.forEach(cb => cb(masked));
    });
  }

  public getMaskedState(participantId: string): RoomState {
    return maskRoomStateForParticipant(this.state, participantId);
  }
}
```

### 3. Reveal Gate Guarantee & Corporate Proxy Safeguards

1. **Reveal Gate Masking**: Every subscriber receives its own independently masked payload generated by `maskRoomStateForParticipant`. In `Voting` phase, peers' card values are strictly `null`, preventing network sniffing in dev tools.
2. **Buffer Flush (`X-Accel-Buffering: no`)**: Hono's `streamSSE` sets this header by default, guaranteeing reverse proxies (NGINX, Cloudflare, AWS ALB) immediately flush chunks without 4KB buffering delays.
3. **Keep-Alive Heartbeats**: The 15-second `: heartbeat` or `event: ping` loop ensures corporate proxies and intermediate stateful NAT firewalls never drop idle SSE streams.
