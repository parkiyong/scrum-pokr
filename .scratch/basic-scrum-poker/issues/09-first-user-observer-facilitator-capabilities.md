# 09: First User Joining as Observer Loses Facilitator Capabilities

**Category:** bug
**Status:** done
**Blocked by:** None

## Description
When the room creator / first user enters a room and joins with the **Observer** role, they should be designated as the Facilitator (e.g. Scrum Master / Agile Coach / Stakeholder orchestrating the poker session without casting estimation points themselves).

However:
1. In [`client/src/hooks/useRoomSocket.ts`](file:///home/widi/GitHub/scrum-poke-ai/client/src/hooks/useRoomSocket.ts), `joinRoom` fired `POST /api/rooms/:code/join` but ignored the response object (`res.json()`), failing to immediately set `setRoomState(data.state)` or sync `participantIdRef.current`.
2. If the real-time SSE stream connection is establishing or experiences a race condition when entering the room, `roomState` remains in an initial unassigned state (`facilitator_id: ""`), causing `isFacilitator` (`roomState?.facilitator_id === currentParticipantId`) to evaluate to `false`.
3. Consequently, the first user joining as Observer did not see the Facilitator Bar (`Start Voting`, `Reveal Cards`, `Finalize Estimate`), deck configuration button, or story backlog controls.

## Root Causes
1. **Client State Desynchronization**: `useRoomSocket.joinRoom` did not apply the immediate masked `RoomState` returned by `POST /api/rooms/:code/join`.
2. **First-Join Fallback & Observer Facilitator Handling**: Ensure `isFacilitator` computation and fallback states seamlessly recognize the room creator as Facilitator regardless of whether their participation role is `Estimator` or `Observer`.
