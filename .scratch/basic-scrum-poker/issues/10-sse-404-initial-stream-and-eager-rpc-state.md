# 10: Real-Time SSE Stream 404 Drop on Room Load and Eager RPC State Synchronization

**Category:** bug
**Status:** done
**Blocked by:** None

## Description
When the Facilitator (or any participant) triggers actions such as **"Start Voting"**, **"Reveal Cards"**, **"Re-Vote Round"**, or **"Finalize Estimate"**, the room state in their browser does not update until they manually refresh the page.

## Root Causes
1. **SSE Initial Connection 404 Error**: In [`server/src/routes/events.ts`](file:///home/widi/GitHub/scrum-poke-ai/server/src/routes/events.ts#L9-L12), `GET /api/rooms/:code/events` called `roomRegistry.get(code)` and returned HTTP 404 if the room actor hadn't been created yet. When a user creates a room with a custom code or joins an existing code via direct URL navigation (`/r/:code`), `EventSource` connected before `POST /join` was sent. The browser received a 404 error and permanently terminated/closed the `EventSource` stream. Subsequent server broadcasts were never received by the client.
2. **Missing State in REST Mutation Responses**: In [`server/src/routes/rooms.ts`](file:///home/widi/GitHub/scrum-poke-ai/server/src/routes/rooms.ts), action endpoints (`/start-voting`, `/vote`, `/reveal`, `/reset`, `/finalize`, `/deck`, `/story`, `/next-story`, `/role`, `/transfer-facilitator`) returned `{ success: true }` without returning the updated masked `state`. In [`client/src/hooks/useRoomSocket.ts`](file:///home/widi/GitHub/scrum-poke-ai/client/src/hooks/useRoomSocket.ts), RPC dispatchers did not update `roomState` from the response, leaving the client exclusively dependent on the SSE stream.

## Acceptance Criteria
- [x] In `server/src/routes/events.ts`, use `roomRegistry.getOrCreate(code)` so `GET /api/rooms/:code/events` establishes an active, persistent stream for valid room codes without returning 404.
- [x] In `server/src/routes/rooms.ts`, return `{ success: true, state: room.getMaskedState(participantId) }` from action endpoints.
- [x] In `client/src/hooks/useRoomSocket.ts`, update RPC action handlers to eagerly apply `data.state` to `setRoomState(data.state)` upon successful HTTP response.
- [x] In `client/src/hooks/useRoomSocket.ts`, ensure SSE stream auto-reconnects if disconnected or errored.
